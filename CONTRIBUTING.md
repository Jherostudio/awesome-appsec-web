# Contributing Guidelines for Awesome Web AppSec

Thank you for your interest in contributing to **awesome-appsec-web**! 🎉

As a community-driven repository, we greatly appreciate suggestions for new tools, resources, security labs, standards, and hardening guides related to Web Application Security (AppSec).

---

## 📋 Quality & Formatting Guidelines

To maintain a clean, professional, and easy-to-navigate list, please make sure your submission complies with the following criteria before submitting a Pull Request:

1. **Relevance**: The item must be directly related to Web Application Security (AppSec), secure coding, DAST, SAST, secret scanning, or web cybersecurity training.
2. **Link Format**: Follow the exact Markdown list format:
   ```markdown
   - [Resource Name](URL) - Concise single-line description explaining the main functionality or purpose.
   ```
3. **Description Rules**:
   - Keep descriptions concise (1 sentence / single-line).
   - Start with a capital letter and end with a period.
   - Maintain a neutral, objective tone (avoid subjective terms like "the best", "amazing", etc.).
4. **Maintenance**: If suggesting an open-source tool or code repository, it must be actively maintained or serve as an essential industry benchmark.
5. **Categorization**: Insert your item into the appropriate section. Maintain a logical order within each category.

---

## 🚀 How to Submit a Pull Request (PR)

1. **Fork** this repository to your GitHub account.
2. **Create a new branch** for your changes:
   ```bash
   git checkout -b add/resource-name
   ```
3. **Edit `README.md`** and add your suggested resource adhering to the guidelines.
4. **Commit** your changes with a clear and concise commit message:
   ```bash
   git commit -m "docs: add [Resource Name] to [Section Name]"
   ```
5. **Push** your branch to your remote repository:
   ```bash
   git push origin add/resource-name
   ```
6. **Open a Pull Request** describing why this resource is valuable to the AppSec community.

---

## 📝 Submission Checklist

Before marking your Pull Request as ready for review, verify that:

- [ ] The link works correctly and uses HTTPS.
- [ ] The description follows formatting rules and ends with a period.
- [ ] There are no duplicate entries in `README.md`.
- [ ] The addition is placed in the correct section.

Thank you for helping make this repository an invaluable resource for developers and security engineers worldwide! 🛡️
